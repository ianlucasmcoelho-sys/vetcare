Correção de 31/10/2026 — login do aplicativo Windows: a inserção da sessão empresarial agora usa `RETURNING token_hash`, evitando o `RETURNING id` automático do adaptador PostgreSQL em uma tabela sem coluna `id`. A falha foi reproduzida antes da correção em teste que usa o adaptador real com um motor SQL local e o schema da sessão; criação, autenticação e logout passam após a correção. A API passa a informar `authVersion: 2` em `/api/company/desktop/health` (mantém `version: 1` por compatibilidade). Erros internos registram somente operação e código, sem senhas, parâmetros SQL ou tokens. O aplicativo existente é compatível: não é necessário reinstalar o `.exe`, recriar contas ou redefinir senhas por causa deste erro.

Verificação de 31/10/2026: 74 testes aprovados (incluindo regressão do adaptador e privacidade dos logs). O teste do adaptador utiliza SQLite como motor SQL local, não uma instância PostgreSQL de produção. O login de produção retornava HTTP 503 antes desta entrega; uma conta inexistente retornava 401. A correção local ainda precisa ser publicada e o login real retestado. O conector Hostinger exigiu nova autenticação, por isso nenhuma publicação foi feita nesta etapa. Banco clínico e credenciais existentes preservados; backup anterior em `backups/antes-atualizacao-2026-10-31-144233/`.


Preparação de contas empresariais em 30/10/2026: o adaptador PostgreSQL identifica o dialeto; a inicialização de contas/sessões empresariais ativa RLS e revoga acesso de PUBLIC e dos papéis anon/authenticated quando existirem. Provisionamento real ainda pendente; nenhuma conta de produção foi criada por esta etapa. A API desktop publicada respondeu 404 na conferência. Os 72 testes continuam aprovados. Não foram incluídos nomes, e-mails ou senhas de provisionamento no pacote.

Atualização de 30/10/2026 — aplicativo Windows: o VetCare Gestão também é entregue como instalador e executável portátil de 64 bits, em arquivos separados deste ZIP. O aplicativo contém suas telas localmente e consulta o servidor atual do VetCare por HTTPS, com contas empresariais individuais. Não precisa hospedar um segundo site nem criar subdomínio ou banco PostgreSQL separado para o painel desktop. Documentação de uso e ativação: `desktop/README.md`.

A publicação da integração `/api/company/desktop` e o provisionamento das duas contas empresariais reais continuam pendentes. O backend passa a criar duas tabelas próprias para contas/sessões dos sócios, preservando os cadastros clínicos. Não há senha padrão nem chave de API/banco/Asaas no executável. Sessões são mantidas em memória no aplicativo, validadas no servidor e separadas das sessões de clínicas. O primeiro login real precisa ser homologado após a publicação.

Verificação do desktop: 72 testes aprovados no conjunto completo, incluindo cliente desktop e API por HTTP, isolamento das contas empresariais, revogação de sessões e falhas de conexão. Executável de Windows aberto e tela de entrada conferida visualmente. Pacote interno inspecionado: somente interface, código do cliente e ícone; sem `.env`, bancos, código do backend ou dependências locais. Auditoria das dependências de build do desktop sem vulnerabilidades reportadas. Banco clínico local preservado, idêntico ao backup anterior. Instalador e portátil não possuem assinatura digital comercial; a ativação e o primeiro login real ainda dependem da publicação do backend e das contas dos sócios.

Atualização de 30/10/2026 — gestão automática: `management/` agora consulta a API privada do sistema VetCare. Clínicas, contatos, acessos e planos são lidos do cadastro original; mensalidades e taxas são conciliadas nas assinaturas Asaas de produção, com cache e atualização automática do painel a cada 60 segundos. Os endpoints de alteração manual ficam desativados por padrão. A API empresarial exige segredo próprio entre servidores e não exporta dados clínicos, senhas ou o caixa das clínicas.

Esta atualização substitui a primeira versão manual entregue na mesma data. A prévia em `http://localhost:3010` utiliza leitura do banco clínico LOCAL, sem escrita ou migração; não usa o banco publicado nem credenciais Asaas de produção. A conexão real ainda requer publicação do backend atualizado, configuração de `COMPANY_API_TOKEN`, aplicação independente em `gestao.vetcaresistema.com`, `MANAGEMENT_SOURCE_URL` e `MANAGEMENT_SOURCE_TOKEN`. Nenhuma publicação ou mudança de DNS foi realizada. Procedimento completo em `management/README.md`.

Validação: 65 testes aprovados, incluindo consulta HTTP entre aplicações, bloqueio de alterações manuais, autenticação, origem, paginação/deduplicação, valores monetários, Sandbox/vitalício, cancelamentos, estornos, vínculos duplicados e falhas do provedor. Layout automático conferido em desktop e celular (390 px) sem vazamento horizontal. Financeiro não conciliado é mostrado como indisponível e não pode ser exportado como CSV parcial. O banco clínico local permaneceu idêntico ao backup. O frontend clínico não foi alterado nesta etapa; o build verificado da entrega anterior está preservado. Limitações: receitas representam cobranças atualmente válidas por mês de pagamento, com taxas identificadas; não são saldo disponível do Asaas, lucro contábil nem livro-caixa histórico de estornos. Despesas externas sem integração não entram automaticamente. PostgreSQL, HTTPS/proxy e consulta ao Asaas real precisam de homologação após publicação. A instalação da gestão usa Node 22.12 ou superior; testes locais executados em 22.11.

O pacote omite os scripts legados de seed/admin com senhas fixas (`backend/src/createAdmin.js`, `backend/src/seed.js`, `backend/scripts/seed_premium.js`, `backend/scripts/seed_test_data.js`). Eles não são necessários à inicialização. Contas reais da gestão são provisionadas por stdin conforme o README próprio; os dados e a senha explicitamente fictícios de demonstração são exclusivos do processo local em memória.
